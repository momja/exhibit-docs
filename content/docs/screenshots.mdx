Save screenshots in `public/screenshots/` and reference them in MDX with paths that start at the site root.

```mdx
![Gallery home](/screenshots/gallery-home.png)
```

Pages can use placeholders such as `/screenshots/gallery-empty.svg` until you have screenshots. Replace placeholders with the images you want to publish. Keep temporary review images out of the repository.

## Capture framework

You'll find the capture tools in `scripts/screenshots/`.

- In `screenshots.config.json`, set which Exhibit and docs pages to capture, the viewport, and the output directory. For signed-in pages, you can set `auth.storageState` for the whole run or `storageState` for an individual shot.
- `capture.mjs` reads the config, visits each route in Playwright Chromium, and writes PNGs to `public/screenshots/`. It exits with status 1 if any shot fails.
- `README.md` in the same folder has the full runbook.

```bash
# Set up once per environment. Install browsers separately from npm packages.
npm install
npx playwright install chromium

# Start both servers before capturing.
#   Exhibit: ./bin/server   (in momja/Exhibit, :8080)
#   Docs:    npm run dev    (here, :3000)

EXHIBIT_URL=http://localhost:8080 DOCS_URL=http://localhost:3000 npm run screenshots
```

## Signed-in captures

You can capture the public docs pages while signed out. If an Exhibit page redirects to sign-in, the runner marks that shot as failed and records the expected and actual URLs. It skips saving the login page.

Sign in through a visible browser window once to create a storage-state file. You can reuse it for one shot or the whole run. See `scripts/screenshots/README.md` for the full steps.

```bash
npx playwright codegen http://localhost:8080 --save-storage=scripts/screenshots/auth-exhibit.json
```

```json
{ "name": "gallery-mine", "path": "/", "waitFor": "main", "storageState": "scripts/screenshots/auth-exhibit.json" }
```

Keep the storage-state file out of the repository. It contains session cookies.

## Fail-loud behavior

The runner reports `PASS` or `FAIL` for each shot. It exits with status 0 if every shot succeeds and status 1 if any shot fails.

A shot fails if any of these happen:

- The browser can't navigate to the page.
- The HTTP status falls outside the 2xx range.
- The page redirects to a login or auth URL.
- The `waitFor` selector never appears.
- The runner can't write the screenshot.

## Conventions

- Use kebab-case filenames such as `gallery-home.png` and `new-artifact.png`.
- Keep each image under about 500 KB. Prefer PNG for interface screenshots.
- List only the shots you want to keep. The runner captures exactly what's in the config.
- Reference each PNG from the relevant MDX page. Keep the SVG placeholder only if the page needs a fallback.
